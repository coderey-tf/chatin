GitHub: https://github.com/coderey-tf/chatin
Live: https://chatin.coderey.dev
Stack: Next.js 16 + React 19 + TypeScript 5 + Supabase (PostgreSQL + Auth + Realtime) + KirimDev SDK (official Meta BSP)
VPS: /var/www/chatin (PM2 chatin, port 3004)
CI/CD: GitHub Actions (.github/workflows/deploy.yml) on push main via SSH & PM2

## Architecture
- KirimDev is official Meta BSP, 10 WA accounts, 1M msgs/mo, Rp199k/mo
- Meta fees pass-through (billed to each client's WABA, not to us)
- Chatin is platform owner, each client = customer with their own WABA
- Chatbot: generic, template-driven, 5 presets (wedding_decor, jasa_rental, klinik, toko_online, generic)
- DB: Supabase PostgreSQL with native JSONB & RLS
  Tables: profiles, customers, setup_links, bot_configs, leads, message_logs, webhook_events, subscriptions, invoices
- Auth: Supabase Auth (Google OAuth + Email/Password) + 3-step Onboarding Wizard
- Layout: Sidebar layout (Sidebar.tsx) with direct routes /dashboard/bot, /dashboard/leads, /dashboard/inbox, /dashboard/billing

## Webhook Flow (v2.3.1 — CRITICAL)
POST /api/webhooks/kirimdev receives Meta Cloud API events from KirimDev.

Real payload format from KirimDev:
```
Headers:
  x-kirim-event: message.received          <-- event type source of truth
  x-kirim-event-id: wamid.HBgNNjI...      <-- message ID
  x-kirim-signature: t=TIMESTAMP,v1=HEX   <-- HMAC signature (t=v1 format, same as Slack)

Body: Meta Cloud API entry format
{
  "entry": [{
    "id": "2259525001457664",
    "changes": [{
      "field": "messages",
      "value": {
        "contacts": [{"wa_id": "6285156266871", "profile": {"name": "Reynaldi"}}],
        "messages": [{"id": "wamid...", "from": "6285156266871", "text": {"body": "tess"}}],
        "metadata": {"phone_number_id": "1265311166666629"}
      }
    }]
  }],
  "kirim": {...}
}
```

Webhook processing:
1. Read x-kirim-event header → set event.type
2. Extract inbound message from entry[0].changes[0].value.messages[0]
3. Find customer by phone_number_id (from metadata) OR fallback to active customer
4. Log inbound to message_logs (enables Supabase Realtime → Live Inbox)
5. If bot_config enabled → run chat engine → auto-reply via KirimDev API
6. Save/update lead to leads table
7. Mark message as read via KirimDev SDK

HMAC verification: wrapped in try/catch (non-fatal on failure, logs warning only)

## Chat Engine Flow & Features
- 4-step funnel: greeting → extract (keyword/date/text/location/select) → completion template + dynamic pricelist link + admin handover → followup
- Levenshtein Fuzzy Typo Detection: isFuzzyMatch in lead-parser.ts tolerates typos up to 2 chars for words >= 4 chars (e.g. Engagnment -> Engagement)
- Dynamic Pricelist Matcher: findMatchingPricelistLink in chat-engine.ts generates synonyms and conflict pairs dynamically from BotField[] config (scoring bonus +10, conflict penalty -15)
- Interactive Sandbox: Live chat simulator in /dashboard/bot with scroller ref, Shift+Enter textarea, and correct user (right/green) vs bot (left/grey) bubbles
- Live Testing Whitelist Mode: Toggle in /dashboard/bot + webhook check allowing bot auto-replies ONLY for whitelisted tester phone numbers (e.g. 085156266871)
- Single-Tenant & Auto-Healing: Enforces max 1 tenant per user account, hiding + Add Customer UI, removing multi-tenant selectors in /dashboard/billing and /dashboard/messages, blocking POST /api/customers, and auto-linking orphan customer records via matching email in listCustomers
- Typing Mode Indicator: Action payload `action: { type: 'typing_on' }` sent via KirimDev/Meta API prior to auto-replies, plus animated typing indicator in Interactive Sandbox Simulator
- Custom ConfirmModal: Replaced native browser `confirm()` with custom glassmorphic dark mode modal component (`src/components/ConfirmModal.tsx`) for destructive actions
- Official shadcn/ui Sonner Toaster: Integrated `sonner@2.0.8` (`src/components/Toast.tsx`) top-right dark mode toast notifications across all dashboard actions
- Ultra-Responsive Live Inbox & Sleek Scrollbar: Custom 6px dark scrollbars in `src/app/globals.css`, Column 3 Slide-Over Drawer on `< xl` screens, and 1-column mobile view with back button
